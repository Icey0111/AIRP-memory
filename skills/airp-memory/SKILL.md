# AIRP 长期记忆纪律

记忆存在本地服务里（MCP 工具 `mcp__airp__memory_*`）。你的职责是**按纪律读写**，
不是自己发明记忆格式 —— 所有枚举、默认值、阈值、能力状态都以 `memory_meta` 为准。

## 每轮对话开始前

1. 调 `memory_context`：`query`(用户消息原文) + `chatId` + **`characterId`(角色卡名，必须传)**。
   画像按角色隔离 —— 不传 `characterId`，【角色画像】段就**整段缺席**，你会看不到人设与既定经历
   （实测踩过：不传就一直没画像）。返回的是已组装好的注入文本：
   角色画像 / 关系立场 / 关键实体 / 前情提要 / 事件时间线 / 待兑现 / 相关记忆 / 相关细节。
2. **把它当作你已经知道的事**，直接用来维持人设与剧情连续性；
   不要向用户复述这些内容，也不要提及"记忆系统""注入"等字样。
3. 若 `capabilities.embedding.available = false`，相关细节段会缺失，属于正常降级，不要报错。
4. **`chatId` 与 `userName` 在整个会话里必须固定不变**。它们不是随手填的标签：
   `chatId` 是所有隔离与判等的基准；`userName` 决定谁是一等节点 ——
   换一次称呼就会多一个"用户本人"节点，立场与画像立刻裂成两套。

## 剧情推进后（写入：每轮都编织）

**每一轮对话后都织一次网**，用 `memory_observe` —— 它内部按
**事件要素 → 属性观察 → 关系立场** 并行跑完三段（互不依赖，所以并发发出），
三段共享同一段文本与同一组来源楼层（这个不变式由服务端保证，你不必自己保证）。

**文本窗口要滑动，这是最容易做错的一点**：

- `text` = 「最近还没被抽取过的那些轮次」，通常 1~3 轮，**包含本轮用户消息 + 你的回复**。
- 若本轮出现指代（"她/他/那家伙/那把匕首"）而**单看本轮判不出指谁**，就把上一轮一起带上。
  单轮裸抽会把指代判错 —— 那是**错记**，比漏记更坏（错的事实会进画像与时间线）。
- `sourceMessageIds` 填这些轮次的楼层 id（当前会话的稳定标识），便于日后追溯。
- **没有新信息的轮次可以跳过**：寒暄、纯确认、和剧情无关的元对话。
  就算抽了，抽取器也会返回空结果，属正常，不是错误。
- `characterName` 传**角色卡原名**、`userName` 传**用户名**：身份锚定的唯一手段，
  漏传会让译名裂成两个人。
- 同一段文本重复抽取由服务端去重（重述只计数），所以**宁可重跑一次，也不要漏写**。

**看返回要读 `steps`**，顶层 `ok: true` 不代表三步都成：

| 返回情况 | 含义 | 你该做什么 |
|---|---|---|
| `steps.<id>.ok = true` | 该步成功 | — |
| `steps.<id>.skipped = true` + `skippedReason` | 能力缺失（如 embedding 未配） | 不用管，正常继续 |
| `steps.<id>.ok = false` + `error` | 该步失败 | 用 `steps: ['<该步id>']` 补跑一次；仍失败就继续剧情，别卡住 |
| 顶层 `partial: true` | 有步未成功 | 同上，按步补 |

可选步 id 以 `memory_meta` 的 `observePipeline` 为准。

## 段落结束 / 会话收尾（沉淀）

调 `memory_summarize`：`chatId` + 整段剧情 `text` + `sourceMessageIds`。
- 这是"前情提要"的唯一来源，漏了会导致后续只能看到零碎观察、看不到脉络。
- 剧情中断处要写一次；会话结束前要写一次。
- 超出 `maxChars` 服务端会自行压缩，不要提前手动概括。

## 需要回溯时

- 要原始命中列表（而不是组装文本）→ `memory_search`
- 要看"谁对谁在某维度上的当前值及迁移史" → `memory_slots`
- 要看已有人物画像 → `memory_list` / `memory_profiles_derive`（观察积累够多时重归纳）

## 红线

- 不要绕过工具直接改记忆数据库文件或投影文本 —— 写入路径只有 MCP 工具，服务端要保证唯一写入口。
- 不要编造 `entityId` / `personId`；不确定就先 `memory_list` 或 `memory_slots` 查出来。
- 不要在回复用户时暴露记忆条目的原始 JSON。

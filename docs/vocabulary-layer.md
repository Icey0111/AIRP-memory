# 词表层 (V10) —— 语义落成可复用的节点

> 状态: **已实现**（迁移 `009_v9_to_v10.sql` + `services/vocabularyService.js` + `cli/vocab.js`）。
> 上游: [`docs/verb-layer.md`](verb-layer.md) §4（原语模型）/ §16（元素先于指针）。
> 图上的读法见 [`docs/graph-view.md`](graph-view.md)。不变式由 `server/test/vocabulary.smoke.js` 钉住。

---

## 1. 一句话

> **谓词 / 题元角色 / 情态 / 从句角色 / 对齐状态 / 观察维度 / 立场类型 / 时段 —— 八个语义域
> 一律落成取值元素（`value_nodes`），实例只存指针；归一到词表在落库前完成，不靠 prompt 自觉。**

这不是洁癖。**谓词不成词表，真假判定就一次都不会生效。**

## 2. 实测证据（2026-10-15，真实库 40 条实例）

| 语义槽 | 迁移前 | 问题 |
|---|---|---|
| `verb_type` 谓词 | 40 条实例 **33 个不同词**，复用度 **1.21**，仅 **20%** 命中词表 | 8 个短语型自造词：`通关入境` `拦截盘查` `出示凭据` `给出最后机会` |
| `event_participants.role` | **12 种**取值，中英各一套（`agent×19`/`施事×9`/`发起者×8`），仅 **25%** 在词表内 | 同一语义两套词源，复用度被摊薄 |
| `events.attitude` | 归属实例 10 条里 **9 种**取值，仅 20% 在枚举内 | `解释盘查从紧` `最后通牒` 是事件复述，不是情态 |
| `parent_role` / `status` | 裸 TEXT，**连 CHECK 都没有** | comp/cond/alt 与七态词表不在库里 |
| `attribute_chunks.aspect` | 15 种取值，**7 英文 + 8 中文自由词**（`appearance` vs `外貌`） | 同一维度两条槽，防吃书的覆盖链失效 |

### 2.1 最严重的后果：真假判定停摆

`alignmentService` 的匹配硬条件是**"同动词"**。谓词是每实例自造的 ⇒ 从句说"去买"、事实写"去" ⇒
**永远不同动词 ⇒ 永不匹配**。实测：10 条归属命题，`aligned_instance_id` 挂上的 **0 条**，
`refuted/failed/inactive/voided` **0 条**，全部停在 `pending`（而且它们都带时间锚 —— 不是"没到点"，是"没钥匙"）。

> 根因有两条，缺一不可（都已在 V10 修掉）：
> ① **活跃路径根本不跑对齐**：`alignPropositions` 只在单步 `extractInstances` 里调用，
>    而 dsh 走的是 `mergedExtraction.extractAll → persistInstances`，从来没跑过对齐。
> ② **谓词不成词表**：即使跑了对齐，字符串比较也几乎不会命中。

## 3. 设计：复用 V7 的元素层，不新增概念

`value_nodes`（V7 §16.4 就写着"**元素先于指针**"）本来就是这张表：`(name, aliases JSON, kind, parent_id)`。
V10 只是把它的域从两个**补齐到七个**，并给实例侧接上指针：

| 域 `kind` | 规范词来源（仍只定义一次） | 实例指针 |
|---|---|---|
| `predicate` | `VERB_LAYER.verbSuggestions` + 上位类 | `events.predicate_id` |
| `role` | `VERB_LAYER.thematicRoles` | `event_participants.role_id` |
| `attitude` | `VERB_LAYER.attitudes` | `events.attitude_id` |
| `clause` | `VERB_LAYER.parentRoles` | `events.clause_id` |
| `status` | `VERB_LAYER.statuses` | `events.status_id` |
| `aspect` | `ASPECT_SUGGESTIONS` | `attribute_chunks.aspect_id` |
| `stance_type` | `STANCE_TYPE_SUGGESTIONS` | `stances.stance_type_id` |
| `time` | `VOCABULARY.timeParents`（昼/夜 + 具体时段） | `time_points.period_id` **（指针-only）** |

> `time` 是唯一的**指针-only** 域：`time_points.label` 是**世界内时刻的名字**（"第三夜, 暴雨"），
> 不是归一后的词，所以它没有文本缓存、不参与漂移检查，归并也只能挪指针、不能改名字。

`value_nodes` 新增四列：`gloss`（说明）、`source`（`seed`/`extracted`/`merged`）、
`status`（`ok`/`needs_review`）、`note`。

### 3.1 文本列保留为"归一后的词"（缓存），不是第二真源

旧文本列（`verb_type`/`role`/`attitude`/`parent_role`/`status`/`aspect`/`stance_type`）**全部保留**，
但只存**归一后的词**，与指针同步写。理由：

- 注入 / 检索 / FTS / 对齐的读路径与**冻结区**都不用改（V10 是加法迁移，零破坏面）；
- 漂移可被机械检出：`auditVocabulary().drift` 必须恒为 0，由 `vocabulary.smoke` 钉住
  （这条断言当天就抓到两处真 bug：对齐服务只改 `status` 文本、`createEvent` 缺省状态写死 `asserted`）。

**纪律：任何改写这些列的地方都必须同时写指针**，统一走 `setVocabValue()`。

### 3.2 缺口由 `createEvent` 兜底

轴③的缺省状态现在由 `entityService.resolveStatus()` 在**唯一插入点**保证：
归属命题默认 `pending`。此前缺省写死 `asserted` ⇒ `createEvent({sourceType:'attributed'})`
会默默把"她说她要去"落成叙述者事实 —— 正是本项目最要防的那件事。

## 4. 归一：机械的一半自动做，判断的一半交给人

```
抽取输出 (自由词)
   │
   ├─ 别名命中 ────────────► 规范词        (agent→发起者 / 外貌→appearance / 声称→说 / 从句→comp)
   │                                        可逆: 别名表删掉即恢复
   └─ 未命中 ──────────────► 新元素 + needs_review
                             原词照原样入库, 按上位类挂好; **绝不静默丢弃、绝不自动拆词**
                                          │
                                          └─► node src/cli/vocab.js merge <域> <源> <目标>   (不可逆, 默认干跑)
```

**宁可不并**（沿用实体归并的纪律）：多一个节点不破坏指针语义，错并会抹掉刻意的区分。
`拦截盘查` 该并进 `问` 还是 `盘查`？机器猜错比不猜更有害 —— 所以它进待审队列。
别名表共 **267** 条，覆盖跨语言（`agent`/`patient`/`recipient`）与中英混用（`外貌`/`习惯`/`关系`）。

### 4.1 谓词上位类：抽象到可高度复用的那一层

具体动词天生又杂又多（实测 33 个/40 条）；上位类只有 11 个：
`言语 感知 位移 交互 给予 取用 攻防 救助 隐瞒 心理 状态`。

```
⟨去⟩ ⟨前往⟩ ⟨抵达⟩ ⟨通关入境⟩      ← 叶子: 具体动词 (复用度低是常态)
        └──────┬──────┘
            位移                    ← 上位类: 复用度的真正落点 (parent_id)
```

实测覆盖：40 条实例里 **24 条**挂上了上位类（言语 10 · 交互 4 · 状态 4 · 感知 2 · 位移 2 · 攻防 2），
即**类级复用度 4.0**，而词级仍是 1.25 —— 抽象层的价值就在这里。

### 4.2 时间点：抽象的是**时段**，不是时刻

时间点有两种身份，必须分开（实测 11 个时间点里 2 个是整句：`暮色中，临近戌时三刻落闸` 被 20 条实例共享）：

| | 是什么 | 在哪 |
|---|---|---|
| **时刻**（time_point） | 世界内的那个具体时间（"第三夜" / "第二夜"） | `time_points.label`，身份由 `UNIQUE(chat_id, label)` 保证 |
| **时段**（period） | 抽象到可复用的那一层（昼 / 夜 / 黄昏 / 清晨…） | `value_nodes(kind='time')`，由 `period_id` 指向 |

**归一绝不改时刻的身份** —— 否则两个不同的夜晚会被并成一个，时间轴直接丢刻度。
所以：

- 时刻 → 时段：`parseTimeLabel()` 从标签里机械抽出时段词（查词表 + 词尾命中："第三夜"/"血月之夜" → 夜）；
  抽不出来就**不挂**（实测 `旅人长途跋涉抵达国门之时` 没有时段词，原样留着进待审），绝不硬塞。
- 时段 → 上位类：`黄昏 → 夜`、`清晨 → 昼`，于是"所有夜间发生的事"一跳即达（实测 10 个时间点归入 夜×9 / 黄昏×1）。
- **整句标签拆开**：`label` 留时段头、修饰语进 `note`（该列一直空着）。
  三条安全线：没有修饰语不动；同聊天已有同名 `label` 则**不拆**；原句一个字不丢地进 `note`。
  实测拆了 2 个：`暮色中，临近戌时三刻落闸` → `暮色中` + `临近戌时三刻落闸`。
- **章节层级**：抽取输出里的 `chapter` 以前被 `findOrCreateTimePoint` **静默丢弃**
  （所以 `parent_id` 实测 0/11 —— 章节从来没进过库）。现在接上：章节作为上级时间点，
  `seq` 跟随首个子节点，它不占时间轴刻度（章节节点上没有实例）。
  ⚠️ 旧数据里的章节**无法回填**（当年就没落库），从下一次抽取开始生效。

## 5. 抽取侧：词表从 constants 注入 prompt

只补词表而不改抽取，等于一边归一一边继续造词。三处改造（`mergedExtraction.js` / `extractionService.js`）：

1. **封闭词表进 prompt**：动词/题元/情态/维度表由 `VOCABULARY_WORDS` **注入**（不是抄一份）；
   `observe.smoke` 断言两处 prompt 都含全部规范词 —— 词表与 prompt 不可能再漂移。
2. **补齐缺失的逻辑结构**：`MERGED_PROMPT` 原先只有 `comp`，`alternatives`/`conditional` 只存在于单步 prompt
   ⇒ 活跃路径上**条件与择一恒为 0 条**（实测 `alt×0` `cond×0`）。现已补齐，并把漂移守卫扩到这三个键。
3. **禁止短语型谓词 + 归属必须有从句**：对象属于 `participants`，动词只回答"做了什么"；
   `attributed` 没给 `comp` 的实例被计数上报（`zone.instances.attributedWithoutComp`）——
   因为宿主"说/问"自己去参与匹配就会泛匹配（§6.1 实测坑）。

## 6. 真假判定：按元素判"同一个词"

```js
samePredicate(a, b) = a.predicate_id === b.predicate_id   // 双方都有指针时
                    ?? a.verb_type === b.verb_type        // 旧行回落字符串比较 (不静默改变判定)
```

于是"前往"与"去"指向同一个元素 ⇒ 从句与事实第一次真的对上了。其余口径**一字未改**：
同动词是硬条件、题元重叠不足保持未决、有未决从句的命题自己不参与匹配（宁缺勿错）。

`mergedExtraction.extractAll` 现在也跑一轮 `alignPropositions`（与单步路径同一条纪律：
失败只 warn，绝不拖垮抽取）。

### 6.1 是否疑问 = 一对 alt 候选

「她问他是否来了」= 宿主 `attitude="问"`（情态枚举新增的那一个）+ **两个 `alt` 候选**
（`polarity="+"` 与 `"-"`）挂在同一宿主下。复用既有的择一竞争机制：谁被事实证实谁兑现，另一个作废。

**零新结构** —— 它只是把 §6.3 的竞争机制用在了"正反"这一对候选上。

### 6.2 与 / 或 / 条件 / 否定的落位（三层，不是一类东西）

| 关系 | 落点 | 说明 |
|---|---|---|
| 或（析取） | `alt` 从句候选 + 竞争 | 抽成两条并行实例 = 凭空编造"两件都发生" |
| 是否（选择问） | `alt` 正反候选 + `attitude=问` | 见 §6.1 |
| 条件 | `conditional` 从句 + `event_links('conditional')` | 前件落空 ⇒ 后果 `inactive`；**威胁本质是条件命题** |
| 与（合取） | **不建结构** | 同一时间节点上的并行实例天然读作"并且"（显式化只会多一条冗余边） |
| 否定 | `polarity` 字段（二值） | 参与对齐：`¬P` 匹配到事实 `P` ⇒ **被推翻**，不是兑现 |

> **口径：关系类型的词进词表（节点），关系本身是边。** 边类型（`event_links.relation`）
> 用 CHECK 词表即可 —— 它们由代码写死，没有"归一/别名"需求，不会漂移。

## 7. 迁移与回填

`009_v9_to_v10.sql` **只做 DDL**（加列 + 索引 + 版本号）：词表内容是语义，
只在 `domain/constants.js` 定义一次，由 `seedVocabulary()` 灌入；把 267 条别名抄进 SQL
等于制造第二语义源。旧数据的机械归一走 `backfillVocabulary()`（只填空指针，**可重复执行**）：

```
[db] 迁移 v9 -> v10 (009_v9_to_v10.sql)
[db] 词表种子: 新建 74 个元素, 补别名/上位类 13 个
[db] 词表回填 (V10): predicate:40 role:65 attitude:8 clause:7 status:40 aspect:50 stance_type:11 time:10;
     新建待审 17 个; 并入旧别名元素 7 个 (aspect:外貌->appearance, aspect:习惯->habit, …);
     拆开整句时间标签 2 个
```

真实库迁移后的对照（同一份数据）：

| 域 | 迁移前 | 迁移后 |
|---|---|---|
| 题元角色 | 12 种 / 复用度 5.42 | **6 种 / 复用度 10.83**（`agent`+`施事`+`发起者` 合成 36 行） |
| 观察维度 | 16 种 / 3.13 | **12 种 / 4.55**（外貌→appearance、陈设→scene 等 7 个旧别名元素被并入） |
| 谓词 | 33 种 / 1.21 | 43 元素 / 1.48 词级，**类级 4.0**（24/40 条挂上上位类），17 个进待审 |
| 时段 | 时间点 11 个，2 个是整句，章节 0 | **10 个挂上时段**（夜×9 / 黄昏×1），2 个整句标签拆开，时段复用度 5.5 |

## 8. 不变式（`test/vocabulary.smoke.js` 钉住）

1. **归一确定性**：跨语言/同义/脏字符（空白、标点、大小写）都落到同一个规范词；词表外如实报未命中。
2. **不丢词、不拆词**：词表外的词原样入库 + `needs_review` + 挂上位类；短语型谓词绝不自动拆。
3. **落库前归一 + 指针**：谓词/题元/情态/从句/状态/维度/立场写入即归一，且指针非空。
4. **零漂移**：`auditVocabulary().drift === 0`（文本缓存必须等于指针所指元素的名字）。
5. **幂等**：种子可反复灌；回填第二次零改动。
6. **★ 真假判定按元素判等**：同义写法（"前往" ≡ "去"）能匹配并兑现，不同动词仍不匹配。
7. **是否/择一是竞争**：恰有一个定局，另一个作废。
8. **归并**：改指针 + 原话进目标别名 + 源元素无残影 + 不产生漂移。
9. **时间点抽象化**：时段归一（夜里/暮色中 → 夜/黄昏）+ 上位类（黄昏→夜、清晨→昼）；
   整句标签安全拆分（撞车不拆、原句进 note）；`chapter` 落成上级时间点；无时段词的标签不硬塞。

## 9. 工具

```bash
node src/cli/vocab.js report [--kind predicate]   # 复用度 / 待审队列 / 孤儿 / 漂移
node src/cli/vocab.js check [--apply]             # 漂移与空指针修复 + 并入旧别名元素
node src/cli/vocab.js merge <域> <源> <目标> [--apply]   # 归并 (不可逆, 默认干跑)
node src/cli/vocab.js seed                        # 重灌种子词表 (服务升级后补新别名)
```

## 10. 非目标与后续

- **不做**：自动拆词/自动归并（不可逆，交给人）；删掉文本列（冻结区与读路径要靠它，且它是归一后的缓存）。
- **后续 A（本文明确留出）**：**实例身份**。目前判等仍走 `label + 来源窗口` / `title + 时间点`
  （V9 口径，动它有数据丢失史）。语义上更该用的是 `谓词元素 + 题元集合 + 时间坐标`，
  但换判等键是一次**有丢数据风险**的改动，需要单独评审 + 回放验证，不混在本轮里做。
- **后续 B**：`/api/meta` 暴露词表与待审数量（面板可以看到"哪些词该整理"）；
  图页面已经能看到待审元素（琥珀虚线框）与时段（时间点侧栏）。
- **后续 C**：`predicateClasses` / `timeParents` 由手工维护 → 可考虑从"类名本身也是合法取值"
  的实测数据里自动归纳。
- **已知边界**：旧数据里的 `chapter` 无法回填（当年就被丢弃了）；历史时间点的 `label` 只有在
  "拆开不撞车"时才被拆，其余保持原样 —— 宁可标签长，不可并掉一个时刻。
